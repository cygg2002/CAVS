## 2. 一页简历推荐版

### 面向低功耗智能摄像头的成本感知端云协同目标检测系统

针对低功耗摄像头算力受限、轻量模型易漏检以及全量上云带宽和时延过高的问题，设计并实现以端侧 YOLO26s、云端 YOLO26x 为核心的端云协同检测原型，覆盖端侧检测、上传决策、JPEG 编码、异步传输、云端复核、结果融合及带框视频输出全链路。

- 设计帧级与 ROI 级双粒度选择性卸载机制，基于端侧置信度、目标尺度、贴边程度、检测覆盖率和图像复杂度等特征，在“不上传、整图上传、ROI 上传”三种动作间进行决策，并通过类别感知 NMS、框替换和新增目标补充完成端云结果融合。
- 自研 Learned v2 轻量上传器，使用逻辑回归预测正收益概率、线性回归预测收益幅度，以“预期检测收益 − 通信代价”为目标联合考虑 payload、带宽、RTT 和队列状态；模型参数以 JSON 部署，在线仅需标准化、向量点积和 sigmoid，适合资源受限端侧执行。
- 在 COCO full 上建立 Edge-only、Cloud-only、人工规则、普通 ROI 和 Learned v1/v2 对照及成本项、云端分辨率、JPEG 质量、Frame/ROI 分支等消融实验；默认平衡点将 mAP50-95 由 0.4733 提升至 0.5829，提升 0.1096，同时将上云比例控制为 42.48%，均摊计算量由全量云端的 209.5 降至 79.8 GFLOPs/image。
- 设计有界异步上传队列、keep-latest/drop-new 调度和 deadline 过期结果过滤，避免 HTTP 与云端推理阻塞摄像头主循环；在 10 Mbps、50 ms RTT、JPEG Q80 仿真下，平均端到端时延为 83.6 ms，相比全量云端的 128.3 ms 降低 34.8%。
- 将端侧 YOLO26s、Learned v2 JSON 参数和传输逻辑移植至 T41+C++ 原型；学习型决策平均耗时 0.676 ms、P95 0.817 ms，50 帧 online 实验将实际上传率控制为 22%；deadline-aware 异步队列将主循环吞吐由同步全上传的 0.614 FPS 提升至约 6.6–6.8 FPS。
- 建立覆盖精度、上传率、KB/image、GFLOPs/image、端到端时延、P95、结果新鲜度和有效 FPS 的评估体系；实现实验日志、决策原因、端侧/云端耗时和融合结果的结构化记录，支持参数扫描、消融分析和问题定位。

## 3. 更精炼的五条版本

- 设计并实现 YOLO26s 端侧检测、YOLO26x 云端复核、选择性上传、异步传输与结果融合组成的端云协同目标检测系统，面向低功耗摄像头和弱网部署场景。
- 提出 Learned v2 成本感知上传器，以轻量分类/回归双头估计云端复核概率和收益，并将 payload、带宽、RTT、队列长度纳入收益-代价决策，实现整图/ROI 双粒度卸载。
- COCO full 实验中，系统将 mAP50-95 从 Edge-only 的 0.4733 提升至 0.5829（+0.1096），上云比例控制为 42.48%，均摊计算量较全量云端降低 61.9%。

- 完成 Learned v2 的 T41 C++/JSON 端侧部署，策略平均开销 0.676 ms、P95 0.817 ms，并在真实 50 帧 online 链路中将实际上传率降至 22%。

## 4. 算法工程师投递版

- 针对固定置信度规则无法识别“上传后真正有收益”的困难样本，构建基于 GT 效用差的监督信号，以 `TP - α·FP` 衡量检测效用，并分别训练帧级/ROI 级的收益概率模型与收益回归模型。
- 设计 15 维图像级特征和 15 维 ROI 级特征，覆盖置信度分布、目标数量与尺度、检测覆盖率、贴边比例、小目标比例和图像边缘复杂度；不引入额外深度网络，降低端侧参数量和推理开销。
- 将上传决策建模为 `P(gain) × E(gain) - λ × Cost(upload)`，通过阈值和代价权重提供精度优先、平衡和带宽优先等可调工作点，而非固定二值规则。
- 设计端云框融合算法：对整图复核执行匹配框替换、端侧稳定框保留和云端新增框补充；对 ROI 结果完成坐标回映射、目标框校正及类别感知 NMS，避免简单拼接导致重复框。
- 在 COCO full 上完成规则策略、Learned v1/v2、普通 ROI baseline、Frame-only/ROI-only、云端输入分辨率、JPEG Q50–Q90、困难子集及指标公平性实验；默认 Learned v2 的 mAP50-95 达 0.5829，较 Edge-only 提升 0.1096。
- 对极小目标、密集目标、贴边目标和高复杂度场景构造困难子集，验证上传器对高收益样本的选择性；同时通过零上传负对照区分融合收益与评估置信阈值造成的指标差异。

## 8. 面试时的两分钟项目介绍

这个项目解决的是低功耗摄像头上轻量检测模型精度不足、但全量上传云端又会造成带宽和时延过高的问题。我采用 YOLO26s 作为端侧实时检测器，YOLO26x 作为云端复核器，系统先在端侧完成检测，再决定当前帧是否不上云、上传整图，或者只上传局部 ROI。

最核心的工作是上传决策。我没有只使用“低置信度就上传”的固定规则，而是设计了 Learned v2 上传器。它从端侧框中提取置信度分布、目标尺度、贴边比例、覆盖率和图像复杂度等轻量特征，使用逻辑回归预测上传后出现正收益的概率，使用线性回归预测收益大小，再减去由 payload、带宽、RTT 和队列长度决定的通信成本。这样可以根据部署环境在精度优先和成本优先之间切换工作点。

在系统侧，我实现了 JPEG 编码、端云协议、云端 YOLO26x 服务、ROI 坐标回映射和端云检测框融合，并设计了有界异步队列、keep-latest/drop-new 调度和 deadline 过期结果过滤，避免网络请求阻塞摄像头主循环。

COCO full 实验中，默认平衡点把 mAP50-95 从端侧单模型的 0.4733 提升到 0.5829，同时只上传 42.48% 的图像，均摊计算量是 79.8 GFLOPs/image。之后我把策略参数导出为 JSON 并移植到 T41 C++ 端，真机策略计算平均只需 0.676 ms；在 online 测试中，50 帧只上传 11 帧。异步队列将同步全上传约 0.614 FPS 的主循环提升到 6.6 FPS 以上。这个项目让我完整经历了从算法设计、指标定义和消融实验，到嵌入式移植、网络链路和真实设备瓶颈分析的过程。

## 9. 可回答的深入追问

### 为什么不直接全量上传云端？

全量上传会持续占用上行带宽和云端算力，并使摄像头主循环受网络 RTT、排队和云端推理影响。真实 T41 实验中，单次 HTTP 与云端推理为秒级，同步全上传只能达到约 0.6 FPS，因此必须采用选择性上传和异步解耦。

### Learned v2 与普通规则有什么区别？

普通规则使用固定阈值判断低置信、小目标或贴边目标，只能描述“看起来困难”，不能判断上传后是否真的改善结果。Learned v2 的标签来自端侧结果与云端复核结果相对 GT 的效用差，直接学习“上传是否有收益”和“收益有多大”，再由系统代价项决定当前网络条件下是否值得上传。

### 为什么使用轻量线性模型而不是神经网络？

上传器运行在低功耗端侧，其任务是利用端侧检测统计量进行决策，不需要重新提取大规模视觉特征。逻辑回归和线性回归可以导出为少量 JSON 参数，C++ 部署简单、可解释且开销低；T41 上平均策略耗时 0.676 ms，证明它不是系统瓶颈。

### ROI 上传如何工作？

ROI 不是只发送检测框坐标，而是围绕端侧候选框按目标大小和贴边情况自适应扩展后裁剪局部图像。云端在裁剪图上重新检测，返回框再根据裁剪区域左上角坐标映射回原图，并与端侧目标进行匹配、替换、补充和 NMS。

### 为什么融合结果可能高于单独 Cloud-only？

Cloud-only 只是 YOLO26x 单模型输出，不是理论上限。融合系统可以保留云端漏掉但端侧正确的稳定框，同时使用云端修正端侧漏检和分类错误，因此候选集合不同。不过这种比较必须保证图像尺寸、置信阈值和 JPEG 编码口径一致，项目中额外设置了指标公平性实验避免错误归因。

### 项目当前还存在哪些问题？

T41 NNA runtime 仍存在间歇性 SIGILL，当前属于研究原型而非量产系统；T41 real100 只有 100 帧 person 类自动参考标注，不能代替大规模人工 GT；Learned v2 online 还需在同一批真实标注帧上补充闭环 AP50。面试中主动说明这些边界，比把原型描述成稳定量产系统更可信。

## 11. 不建议在简历中直接写的表述

- 不写“已实现稳定量产部署”，应写“完成 T41 真实设备原型验证”。
- 不写“T41 真实数据人工 GT”，当前应写“SpeciesNet 自动参考标注”或不在一页简历中展开。
- 不写“Learned v2 在 T41 上将 AP50 提升到 0.4835”，该 AP50 来自规则近全上传结果，不是 Learned v2 online 闭环结果。
- 不把不同 `imgsz`、JPEG 质量和置信阈值下的 mAP 直接比较为模型优劣。
- 不只写“优化精度和速度”，应至少保留一个精度指标、一个成本指标和一个真机指标。
