# V1.0 修订说明

## 版本定位

- 基线：`V0_9_20260726_auditable_costaware_router_zh_final`。
- 新题目：**端云协同目标检测的成本感知上传配置选择**。
- 英文题目：**Cost-Aware Upload Configuration Selection for Edge-Cloud Object Detection**。
- V0.9 原目录与原 DOCX 未修改；V1.0 使用独立目录、源稿和构建产物。

## 主题与叙事变化

1. 论文主语由“风险受控配置采纳”改为“成本感知上传配置选择”。
2. 在线端云执行链路成为方法主体：端侧检测、上传优先级、预算接纳、载荷选择、云端复核与融合。
3. 离线控制器选择完整配置 `Ranker × Payload Policy × Budget Mode × Parameters`。
4. 独立经验门禁、回退、冻结和审计降为部署保护层，不再作为主要在线上传创新。
5. 八个 Ranker 按启发式、收益预测/排序、思想代理/组合基线分组；SemanticRank 被限定为多载荷修复收益的轻量成对排序实例，Controlled-32D 只作消融。
6. SharedAction 用于解耦样本优先级与载荷选择；CostEligible-AllROI 明确为简单启发式消融；GBDT-Hierarchical 为学习型 ROI 候选，不宣称跨域普遍有效。
7. 结果按总体精度—通信成本、上传哪些图像、上传什么、预算语义、跨域复用和部署保护组织。

## 新纳入的补充实验

数据源：`paper/experiments/20260727_three_dataset_costaware_submission_ablation`。

- Random Online/Fixed-byte 50 种子三数据集结果；Fixed-call 沿用同源随机结果。
- 200/1000/2000 次 paired percentile bootstrap 敏感性。
- 三域共享排序器族与载荷策略的事后严格可行性诊断。
- 完整协议、无门禁、无成本目标、固定 Confidence+SharedAction 的组件损伤诊断。

这些补充实验不改变既有冻结配置。跨域统一配置和组件损伤均读取了已经查看过的终评，只作为事后机制诊断，不冒充新的隐藏终评。

## 关键结论边界

- 冻结配置相对参考配置：0/30 次超过 `ε=0.001` 的终评退化容忍。
- 完整协议平均请求字节变化仅 `-0.23%`，不能宣称普遍大幅节省。
- 无门禁诊断出现 5/30 次容忍违反，但平均节省更多字节，门禁存在误拒成本。
- AP-only selector 在事后诊断中未劣于成本目标，因此不主张成本目标模块具有独立增益。
- COCO 10/10 个冻结工作点超过相同预算下的 50 种子经验随机上界；ENA24 和 Oregon 分别为 3/10 与 5/10。
- 三域严格共享同一排序器族与载荷策略的可行工作点为 0/10。
- ROI 在冻结配置中多数低于 0.6%，不主张 ROI/GBDT 跨域普遍有效。
- 没有忠实外部基线和当前冻结配置的同协议真机测试；二者继续列为发表证据缺口。
