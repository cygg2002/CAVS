## 摘要

低功耗智能摄像头在野外监测、安防巡检和无人值守感知等场景中具有广泛应用，但其端侧计算资源有限，难以长期运行大规模目标检测模型。轻量化端侧模型虽然能够满足实时响应需求，但在小目标、遮挡、复杂背景和低置信场景中容易出现误检、漏检和分类错误；云端大模型具有更高检测能力，但全量上传图像会带来较高通信带宽、网络延迟和云端计算成本。针对上述问题，本文提出一种面向低功耗智能摄像头的成本感知端云协同目标检测方法。该方法以 YOLO26s 作为端侧轻量检测模型，以 YOLO26x 作为云端复核模型，构建包含端侧检测、上传决策、异步传输、云端复核和结果融合的协同检测框架。为降低无效上传，本文设计帧级与 ROI 级双粒度上传机制，并提出成本感知学习型上传决策器，根据端侧检测置信度、目标尺度、图像复杂度、上传数据量、网络状态和队列状态估计云端复核收益，从而在检测精度、上传量、端到端延迟和均摊计算量之间进行权衡。在 COCO full 数据集上的实验表明，所提 Learned v2 方法在默认平衡点上将 mAP50-95 从 Edge-only 的 0.4733 提升至 0.5829，同时将上传比例控制在 0.4248，均摊 GFLOPs/image 为 79.8，明显低于全量云端检测。真实 T41 摄像头实验进一步表明，JPEG q70/w640 上传约为 40 KB/image，板端 JPEG 编码约 82 ms；异步上传可将同步云端链路下约 0.9 FPS 的处理速度提升到 10 FPS 量级；规则选择性闭环在 100 个真实板端样本中将上云比例控制为 37%，37 次上云全部成功。实验同时暴露出 T41 NNA 运行时的间歇性 SIGILL 和真实场景标注不足问题，说明真实低功耗部署需要同时考虑检测策略、传输调度、硬件运行时稳定性和真实数据评估边界。

关键词：端云协同；目标检测；边缘智能；智能摄像头；实时图像处理；上传决策

## 1. 引言

随着边缘智能和智能摄像头的发展，目标检测模型越来越多地部署到资源受限的端侧设备中。与传统将视频流全部传输到云端的方案相比，端侧目标检测能够减少原始数据传输，降低隐私风险，并缩短本地响应时间。然而，在低功耗摄像头、嵌入式处理器和移动边缘设备上，模型参数量、计算量、内存占用和功耗都受到严格约束，端侧通常只能部署轻量化检测模型。这类模型在常规场景中可以提供较高帧率，但在复杂背景、小目标、遮挡、运动模糊和低光照等场景下容易产生误检和漏检。

云端强模型可以在更大的算力和显存条件下运行，通常具有更高检测精度和更强泛化能力。如果将所有图像上传云端检测，系统可以获得较高精度，但这种方案并不适合低功耗摄像头和弱网部署场景。一方面，连续上传图像或视频流会消耗大量带宽；另一方面，网络往返延迟、队列等待、云端推理和结果返回会增加端到端延迟，难以满足实时视觉系统要求。此外，全量云端检测会持续占用云端 GPU 资源，在多摄像头或大规模部署场景中成本较高。

端云协同推理为上述矛盾提供了一种折中思路：端侧轻量模型负责实时检测和初步判断，云端强模型仅对端侧不确定或高价值样本进行复核。理想的协同系统不应简单地“全部上云”或“固定周期上云”，而应根据当前帧的检测难度、潜在收益、图像大小、网络状态和云端计算成本动态决定是否上传。对于目标检测任务，上传粒度也比分类任务更复杂：系统既可以上传整帧图像，也可以围绕端侧检测框裁剪局部 ROI 进行云端复核。不同上传粒度对应不同的带宽开销、检测收益和融合策略。

现有简单协同策略多依赖人工规则，例如低置信框上传、小目标上传、贴边目标上传或周期性关键帧上传。这些规则具有一定可解释性，但难以稳定区分“真正值得上传的困难样本”和“上传后收益很小的低价值样本”。在弱网环境中，过多无效上传会导致队列积压和实时性下降；在云端资源有限时，低价值请求也会浪费计算资源。因此，需要一种能够同时考虑检测收益与上传代价的资源感知上传决策方法。

本文围绕低功耗智能摄像头场景，提出一种成本感知端云协同目标检测方法。系统端侧运行 YOLO26s 等轻量化检测模型，云端运行 YOLO26x 等强检测模型。端侧首先对每帧图像进行实时检测，并根据检测结果提取图像级和 ROI 级特征；随后，学习型上传决策器估计整图或 ROI 上传后的潜在收益，并扣除由图像大小、带宽、RTT 和队列状态带来的传输代价；当上传收益大于代价时，系统将整图或 ROI 上传至云端复核；云端检测结果再与端侧检测框进行融合，得到最终输出。

本文主要贡献如下：

1. 提出一种面向低功耗智能摄像头的实时端云协同目标检测框架，统一端侧轻量检测、云端强模型复核、传输调度和检测结果融合。
2. 设计帧级与 ROI 级双粒度上传机制，使系统能够根据当前样本难度选择整图复核或局部复核，从而降低不必要的数据传输。
3. 构建成本感知学习型上传决策器，将云端复核的预期检测收益与上传代价联合建模，避免仅依赖固定置信度阈值导致的低价值上传。
4. 在 COCO full 数据集和 T41 摄像头平台上从 Precision、Recall、mAP、上传比例、KB/image、GFLOPs/image、端到端延迟、FPS、JPEG 编码成本、异步队列和端侧 NNA 稳定性等维度验证方法有效性与工程边界。

## 2. 相关工作

### 2.1 轻量化目标检测与端侧部署

实时目标检测模型在智能监控、无人机、机器人和车载感知等场景中应用广泛。YOLO 系列检测器通过单阶段检测结构在速度和精度之间取得较好平衡，适合实时视觉任务。为了适配端侧设备，研究者通常通过缩小模型宽度和深度、降低输入分辨率、结构重参数化、剪枝、量化和硬件加速等方式降低模型计算量。轻量化模型能够显著提升端侧推理速度，但模型容量降低后，在小目标、遮挡目标和复杂背景下更容易出现检测错误。

端侧部署还受到硬件生态和算子支持限制。以低功耗智能摄像头为例，设备通常具备摄像头接口、ISP、硬件 JPEG/H.264/H.265 编码器以及有限的 CPU/NPU 算力。与 Jetson 等通用边缘 GPU 平台不同，T41 这类摄像头处理平台更接近真实低功耗产品形态，但模型迁移通常需要 ONNX 转换、INT8 量化、NPU 编译和算子适配。因此，在论文实验中需要区分算法有效性验证与硬件链路可行性验证，避免夸大端侧模型部署能力。

### 2.2 端云协同推理与选择性上传

端云协同推理通过将部分计算任务放在端侧、部分高开销任务放在云端，实现精度、延迟和资源消耗之间的折中。常见方法包括早退推理、模型切分、选择性卸载、关键帧上传和云端复核等。对于图像分类任务，选择性上传通常只需要判断整张图是否困难；而在目标检测任务中，端侧输出是多个目标框，系统既需要判断当前帧是否整体困难，也需要判断某些局部目标是否值得云端复核。

已有端云协同工作往往关注整体任务卸载，或者将低置信样本上传至云端。此类方法实现简单，但上传决策通常与真实检测收益之间存在偏差。例如，低置信检测框不一定是错误框，上传后可能没有任何收益；相反，一些高置信错误或端侧漏检目标可能无法被简单规则捕捉。因此，目标检测中的端云协同需要更细粒度地建模端侧检测特征、场景复杂度、上传粒度和云端复核收益。

### 2.3 实时视觉系统中的资源感知决策

实时图像处理系统不仅需要关注算法精度，还需要关注端到端延迟、帧率、带宽、计算量和任务队列。在摄像头场景中，连续帧之间存在大量冗余，如果对所有帧进行云端复核，会造成重复上传和计算浪费。弱网环境下，上传任务积压会进一步增加延迟，导致云端返回结果已经过期，无法服务当前实时画面。

因此，实时端云协同系统需要将网络状态和任务队列纳入决策。本文将上传代价显式引入决策分数，并预留带宽、RTT 和队列长度等动态因素。与只报告模型推理速度不同，本文关注从摄像头采集、端侧检测、上传决策、图像编码、网络传输、云端推理、结果融合到返回输出的完整链路，以满足实时图像处理期刊对 real-time issues 的要求。

## 3. 系统总体架构

### 3.1 系统组成

本文系统由端侧检测模块、上传决策模块、端云传输模块、云端复核模块和结果融合模块组成。端侧设备面向 T41 + 摄像头等低功耗智能摄像头平台，负责图像采集、轻量检测、特征提取、上传决策和图像编码；云端服务器部署 YOLO26x 等强检测模型，负责对上传的整图或 ROI 进行高精度检测；融合模块根据上传类型将端侧框和云端框合并为最终检测结果。

系统数据流如下：

```text
摄像头采集
  -> 当前帧 frame
  -> 端侧 YOLO26s 检测，得到 edge_boxes
  -> 提取图像级特征和 ROI 级特征
  -> 成本感知上传决策
       -> 不上传：直接输出 edge_boxes
       -> 整图上传：上传 frame 到云端 YOLO26x
       -> ROI 上传：裁剪局部 roi_crop 上传云端 YOLO26x
  -> 云端返回 cloud_boxes
  -> 端云结果融合
  -> 输出 final_boxes
```

该架构的核心思想是：端侧始终保持实时检测能力，云端只在端侧不确定或预期收益较高时介入。这样可以避免将云端作为每帧检测的必要环节，从而降低弱网环境下的阻塞风险。

### 3.2 端侧检测模块

端侧检测模块使用 YOLO26s 等轻量检测模型。对于每一帧输入图像，端侧输出检测框集合：

```text
E = {e_i | e_i = (x1_i, y1_i, x2_i, y2_i, c_i, s_i)}
```

其中 `(x1_i, y1_i, x2_i, y2_i)` 表示检测框坐标，`c_i` 表示类别，`s_i` 表示置信度。端侧检测结果既可以作为本地实时输出，也可以作为上传决策和 ROI 生成的依据。

在 T41 实验中，端侧模块分为两个层次。第一层为必须完成的摄像头链路，包括图像采集、编码和上传；第二层为端侧检测部署，如果 YOLO26s 完成 NPU 适配，则在 T41 上运行完整端侧检测，否则在算法实验平台上评估 YOLO26s，同时在 T41 上验证真实摄像头传输链路。论文写作中将如实区分这两类实验。

### 3.3 上传决策模块

上传决策模块根据端侧检测结果判断当前帧或局部 ROI 是否需要云端复核。该模块包含两个分支：

- 帧级分支：判断整帧图像是否值得上传；
- ROI 级分支：判断某个端侧检测框附近的局部区域是否值得上传。

帧级分支主要处理整体复杂、端侧空检、检测稀疏或疑似漏检场景。ROI 级分支主要处理低置信、小目标、贴边目标或局部困难目标。两个分支共享图像级上下文特征，但使用不同的特征向量和决策阈值。

### 3.4 端云传输模块

端云传输模块负责将图像数据和元数据发送到云端。为了降低通信开销，实际部署中优先采用 HTTP multipart 或 gRPC，而不是 JSON + base64。一次上传包含：

```text
image.jpg 或 roi.jpg
frame_id
timestamp
payload_type
orig_shape
crop_xyxy
edge_boxes
decision_score
p_gain
expected_gain
jpeg_quality
```

在实时系统中，上传队列不能无限增长。本文建议将端侧上传队列限制为较小长度，例如 `queue_size <= 2`，并在网络拥塞时丢弃过期任务或仅保留最新高价值任务。这样可以避免云端返回过期检测结果，保证系统服务于当前画面。

### 3.5 云端复核模块

云端复核模块部署 YOLO26x。若上传类型为整图，云端直接在整帧图像上检测；若上传类型为 ROI，云端在局部裁剪图上检测，并将检测框根据 ROI 左上角坐标映射回原图坐标。云端返回结果包括：

```text
cloud_boxes
cloud_infer_ms
cloud_decode_ms
fusion_ms
request_id
```

这些信息既用于输出最终检测结果，也用于后续统计端到端延迟和分析系统瓶颈。

### 3.6 结果融合模块

融合模块根据上传类型采用不同策略：

- 不上传时，`final_boxes = edge_boxes`；
- 整图上传时，系统可直接采用云端结果，也可基于 IoU 对端侧和云端结果进行融合；
- ROI 上传时，云端 ROI 检测框先映射回原图，再与目标端侧框匹配。匹配成功时使用云端框修正端侧框；未匹配且端侧框置信度较低时可删除端侧框；云端发现额外高置信目标时可补充到最终结果；最后执行类别感知 NMS。

这种融合方式避免了简单拼接造成的重复框问题，也避免了云端结果完全覆盖端侧稳定结果。

## 4. 成本感知帧级-ROI级上传方法

### 4.1 图像级特征

图像级特征用于描述当前帧整体是否困难。给定当前帧和端侧检测框集合，系统提取以下统计量：

```text
image_complexity: 图像边缘密度，用于近似场景复杂度
det_count: 端侧检测框数量
coverage: 端侧检测框覆盖面积比例
max_conf / mean_conf / min_conf: 端侧置信度统计
conf_std: 置信度波动
empty: 端侧是否空检
sparse: 检测是否稀疏
low_coverage: 检测覆盖是否过低
mean_area / max_area: 检测框面积统计
edge_box_ratio: 贴边目标比例
low_conf_ratio: 低置信目标比例
small_box_ratio: 小目标比例
```

这些特征计算开销低，不需要额外深度网络，适合端侧实时运行。

### 4.2 ROI 级特征

ROI 级特征围绕单个端侧检测框构建。对每个候选框，系统提取：

```text
conf: 端侧框置信度
inv_conf: 1 - conf
relative_conf: 相对整图平均置信度
area / log_area: 目标面积占比
aspect_log: 宽高比
edge_margin: 距离图像边界的距离
is_small: 是否小目标
is_edge: 是否贴边目标
center_x / center_y: 目标中心位置
coverage_share: 该框在检测覆盖面积中的占比
image_complexity: 图像复杂度
det_count: 整图检测数量
coverage: 整图检测覆盖率
```

ROI 不是端侧框本身，而是由端侧框扩展得到的局部图像区域：

```text
roi_xyxy = expand(edge_box.xyxy, gain)
roi_crop = frame[roi_y1:roi_y2, roi_x1:roi_x2]
```

其中 `gain` 根据目标大小和贴边情况自适应调整。小目标和贴边目标使用更大扩展倍率，以避免裁剪掉关键上下文。

### 4.3 收益-代价决策函数

本文将上传决策建模为收益与代价的联合优化问题。对候选上传任务，定义分数：

```text
S = P_gain * G_exp - λ * C_upload
```

其中，`P_gain` 表示上传后带来正收益的概率，`G_exp` 表示预期收益大小，`C_upload` 表示上传代价，`λ` 为代价权重。上传代价首先由图像编码大小估计：

```text
C_upload = payload_kb / 100
```

在真实网络部署中，代价项可以进一步加入带宽、RTT 和队列长度：

```text
C_upload = payload_kb / 100
           * (10 / uplink_mbps)
           * (1 + queue_len)
           * (1 + RTT_ms / 100)
```

该公式体现三个直觉：上传图像越大代价越高；上行带宽越低代价越高；队列越长或 RTT 越高，当前上传越可能影响实时性。

### 4.4 学习型上传器

学习型上传器包含四个轻量预测头：

```text
frame_model:        预测整图上传产生正收益的概率
frame_value_model:  预测整图上传收益大小
roi_model:          预测 ROI 上传产生正收益的概率
roi_value_model:    预测 ROI 上传收益大小
```

概率头采用逻辑回归，收益头采用线性回归。模型推理只需要标准化、向量点积和 sigmoid 运算，参数可保存为 JSON，因此适合部署在资源受限设备或 C/C++ 程序中。

训练标签由端侧结果和云端结果相对于 GT 的目标级效用差生成：

```text
utility = TP - α * FP
gain = utility_after_upload - utility_before_upload
```

其中 TP 表示与 GT 同类别且 IoU 大于阈值的正确检测，FP 表示误检，`α` 为误检惩罚系数。当 `gain > utility_margin` 时，该样本被标记为上传正样本；同时，归一化后的 `gain` 用于训练收益回归头。这样，学习器不是简单模仿人工规则，而是学习“上传后是否真的提升最终检测结果”。

### 4.5 在线决策流程

推理阶段，系统先计算整图上传分数：

```text
frame_score = P_frame * max(0, G_frame) - λ * C_frame
```

若满足：

```text
P_frame >= frame_threshold
and frame_score > 0
and upload_queue_not_full
```

则上传整帧图像。若整图不上传，则遍历端侧检测框，计算每个 ROI 的上传分数：

```text
roi_score = P_roi * max(0, G_roi) - λ * C_roi
```

系统选择满足阈值且分数最高的 Top-K 个 ROI 上传。若没有候选满足条件，则当前帧不上云，直接输出端侧结果。

## 5. 实验设置

### 5.1 数据集与模型

离线算法实验采用 COCO full 数据集：

```text
训练集: COCO train2017
验证集: COCO val2017
端侧模型: YOLO26s
云端模型: YOLO26x
端侧输入尺寸: 640
云端输入尺寸: 512
端侧部署置信度: 0.25
云端部署置信度: 0.25
JPEG quality: 80
```

真实系统实验采用 T41 + 摄像头平台。T41 实验用于验证摄像头取帧、NV12 图像处理、板端 JPEG 编码、HTTP multipart 上传、云端 YOLO26x 复核、JSON 结果返回、异步上传队列和端侧 YOLO26s NNA 运行状态。需要强调的是，COCO 离线实验用于验证检测策略的精度和成本折中；T41 实验用于验证真实低功耗摄像头链路中的编码、传输、队列和运行时成本。由于当前真实 T41 视频尚未完成逐帧人工标注，T41 部分不报告真实场景 mAP，而报告延迟、上传量、成功率、FPS 和稳定性。

### 5.2 对比方法

本文设置以下对比方法：

| 方法 | 说明 |
| --- | --- |
| Edge-only | 仅使用端侧 YOLO26s，完全不上云 |

其中，Ordinary ROI+Cloud 用作普通 ROI 上传 baseline，用于检验本文方法是否只是简单地把端侧低置信候选框送到云端复核。

### 6.7 T41 摄像头链路与真实系统成本

表 6 汇总了 T41 真实 JPEG 上传实验。JPEG q70/w640 的平均 payload 约为 40.053 KB，编码时间约为 82.069 ms，HTTP 往返约为 1503.373 ms，云端 YOLO26x 推理约为 1123.246 ms。关键帧上传将上传比例降至 0.200 后，FPS 从全帧同步上传的约 0.57 提升到约 2.4-2.5。该结果说明，板端 JPEG 编码本身已经是几十毫秒级开销，而真实云端链路主要瓶颈来自 HTTP 往返和云端推理。

队列长度消融显示，q1/q2/q3 的 FPS 均保持在约 10.5 FPS，完成上传数分别为 7、8 和 9，drop 数分别为 13、12 和 11。较大队列可以提高上传完成数量，但也可能增加结果陈旧风险。实际部署中可根据任务选择：若实时告警优先，使用较小队列并保留最新高价值任务；若离线复核优先，可以适当增加队列长度。

T41 NNA 稳定性实验表明，YOLO26s 和 YOLO26n 在成功推理时输出稳定，但运行时存在间歇性 SIGILL。含失败 attempt 的统计中，YOLO26s 10 次尝试成功 4 次、SIGILL 6 次，平均成功推理约 593.372 ms；YOLO26n 成功 5 次、SIGILL 5 次，平均成功推理约 245.824 ms。按 success-only 口径统计，YOLO26s 的 20 个成功样本平均推理为 585.971 ms，p95 为 701.825 ms；YOLO26n 平均推理为 228.497 ms。该结果说明端侧模型部署的瓶颈不仅是精度和速度，也包括 NNA runtime 稳定性。

E21 闭环实验进一步验证了同一帧上端侧 YOLO26s、JPEG 上传、云端 YOLO26x 和返回结果的可运行性。早期 B5 rule 闭环样本可以证明链路跑通，但日志中过多 `edge_empty` 记录使其不适合作为最终规则策略证据。修正后的 selective rule 版本在 100 个真实板端样本上完成闭环，其中 37 个样本被决策上云，37/37 上传成功，上传比例为 0.370；单次上云 payload 为 22.870 KB，摊销到全部样本为 8.462 KB/frame；平均端侧 YOLO26s 推理为 616.395 ms，平均 HTTP 往返为 1532.018 ms，平均云端 YOLO26x 推理为 1114.861 ms。决策原因包括 `edge_confident:63`、`keyframe:17`、`low_conf:11`、`edge_failed:6` 和 `small_object:3`。因此，E21 当前可以作为真实 T41 规则选择性上云的链路与成本证据；但由于板端视频样本没有人工标注，E21 仍不能报告真实场景 mAP，也不能替代 COCO 上的检测精度评估。

## 7. 讨论

### 7.1 精度与成本折中

实验结果说明，端云协同系统的价值不在于始终取得最高单点精度，而在于提供可调工作点。实际部署中，不同场景对精度、带宽和延迟的需求不同。野外弱网摄像头可能更关注低上传量和稳定延迟，而离线质检或高风险监控场景可能更关注精度。本文方法通过调节阈值和代价权重，使系统能够根据部署条件切换工作点。

### 7.2 ROI 分支的边界

ROI 上传可以降低单次上传数据量，并在局部困难目标上提供云端复核机会。但 ROI 不是无条件有效。一方面，裁剪 ROI 会放大小目标并减少背景干扰；另一方面，过小的 ROI 也可能丢失上下文，导致分类错误。当前 COCO full 结果中，整体收益主要来自帧级选择性上传，ROI 分支仍有继续优化空间。后续可以结合视频时序记忆、小目标数据集和更强 ROI 选择器进一步提高 ROI 分支收益。

### 7.3 T41 部署限制

T41 + 摄像头更接近真实低功耗智能摄像头形态，但其模型部署生态与通用 GPU 平台不同。实验表明，YOLO26s 可以在 T41 NNA 上得到稳定的成功样本输出，但当前 runtime 存在间歇性 SIGILL，需要进程级重试或运行时修复。本文因此不把 T41 结果包装成“稳定量产部署”，而是将其作为真实低功耗摄像头原型验证：摄像头采集、JPEG 编码、HTTP 上传、云端复核、异步队列和规则选择性端云闭环均可运行，但要形成稳定长期部署，还需要修复 NNA runtime，并进一步补充真实视频标注精度评估或学习型上传器上板验证。

### 7.4 泛化性

学习型上传器在 COCO 上训练和验证，迁移到 CCT、VisDrone、BDD100K 或真实野外摄像头后，端侧错误分布、目标尺度和图像复杂度可能变化。因此，跨场景部署时需要重新校准阈值，必要时重新训练上传器。本文后续将通过真实 T41 摄像头视频或第二数据集小样本进一步验证方法鲁棒性。

## 8. 结论

本文提出一种面向低功耗智能摄像头的成本感知端云协同目标检测方法。该方法利用端侧轻量模型进行实时检测，并通过学习型上传决策器选择高价值整图或 ROI 上传云端复核，从而在检测精度、上传量、端到端延迟和计算量之间取得折中。COCO full 实验表明，所提 Learned v2 方法相比 Edge-only 显著提升检测精度，并相比 Cloud-only 大幅降低均摊云端计算量和上传需求；普通 ROI baseline 对比进一步表明，简单裁剪低置信候选框上传云端并不能取得同等精度-成本折中；成本项、云端输入尺寸、Frame / ROI 分支和 JPEG quality 消融验证了各模块的作用边界；弱网和队列实验进一步表明，选择性上传在 10 Mbps/50 ms RTT 和连续帧 deadline 场景下比全量云端检测更适合实时链路；困难子集、上传选择性和指标公平性实验说明，学习器主要选择高收益困难样本，并避免把指标口径差异误解释为云端贡献。真实 T41 板端实验进一步验证了 JPEG 编码上传、异步云端复核、端侧 YOLO26s NNA 推理和闭环原型的可行性，同时暴露出 NNA runtime 稳定性和规则日志解析问题。后续工作将优先修复 E21 规则决策日志，补充真实视频标注集上的 mAP 评估，并进一步将网络状态感知和视频时序记忆纳入上传器。
