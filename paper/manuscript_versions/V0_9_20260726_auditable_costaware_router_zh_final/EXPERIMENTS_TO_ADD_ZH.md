## P1-1 统一配置消融（riskgate 阶段 6，最高优先）

**为什么补**：论文核心结论"不存在跨域统一最优的排序器或载荷策略"目前只有两条诊断级证据（冻结选择分布 + oracle 分布），没有直接对照实验——审稿人只需一句"你没跑过统一配置，怎么知道它差多少"即可动摇发现 1。精读的 24 篇中，NoScope 的因素分析、Chameleon 的逐组件消融、ApproxDet 的每组件验证图都表明配置消融是该领域的标配。这也是 20260725 riskgate 实验 PLAN 中预注册但未执行的阶段 6，补齐后论文可删除"消融未执行"的自我限定。

**如何补**：
1. 仅用三域 calibration/selector 数据，为每个工作点（10 个）选择一个跨域共享的全局配置：目标函数与 4.4 节相同，但约束改为三域共用同一（排序器，载荷策略）组合，逐域校准阈值；
2. 该全局配置在各域门禁集上跑与主实验相同的 200 次配对 bootstrap 门禁；
3. 打开终评（每域 10 行，配置在 240 候选终评表中已存在或按冻结管线评一次）；
4. 输出四方对比表：dataset-adaptive（本文主结果）vs global-one-config vs reference vs final oracle，指标为 AP、KB/图、回退率、oracle regret。

**实现**：扩展 `20260725_.../scripts/selector_core.py` 的候选枚举逻辑（加跨域一致性约束），复用 `run_audit_gate.py` 与 finalizer；新建实验目录（如 `20260727_three_dataset_global_config_ablation`）,遵循同样的协议冻结→选择→门禁→终评顺序。

**判据与写法**：若 global 配置显著更差（AP 或字节），发现 1 升级为有对照的确认性表述；若差距不显著，如实改写 6.5 节为"统一配置的代价在当前域集合上有限"——两个方向都有发表价值，不许挑方向。

## P1-2 组件损伤研究（lesion study）

**为什么补**：主题 C 把"校准-门禁-回退"协议立为贡献 1，但论文没有量化"去掉门禁会怎样、去掉成本目标会怎样"——只有 COCO 一段文字。NoScope 的 lesion study 模式（逐个移除组件看掉多少）是让协议价值可视的最低成本方式。

**如何补**（全部为对已有终评行的 post-hoc 重分析，不产生新的终评评测，论文中须标注诊断口径）：
1. **无门禁变体**：直接部署各工作点的 provisional 候选，从 240 候选终评表（ENA24：`final_candidate_results.csv`；COCO/Oregon：上游 `results.csv` 的 final 行）读取其终评 AP/KB；统计 ε 违反次数与最大违反幅度；
2. **无成本目标变体**：选择集上只按 AP 最高选（忽略字节），同法读取终评行；
3. **固定基线变体**：全部工作点固定 Confidence + SharedAction；
4. 输出对照表：完整协议 / 无门禁 / 无成本目标 / 固定基线 ×（ε 违反次数、平均 AP 差、平均字节、regret）。

**判据**：预期"无门禁"在 COCO 出现终评 AP 违反（已知门禁集下界 -4.2~-3.3×10⁻³，终评是否真violate需要复算——若终评未违反，则如实报告并把门禁价值表述为"拦截了门禁集证据不足的候选"而非"避免了终评违反"）。

## P1-3 bootstrap 敏感性与功效增强

**为什么补**：M3 指出 200 次重采样估计 2.5%/97.5% 分位数时每侧尾部仅约 5 个点，且未做多重性控制；表 8 显示功效不足是保守性主因。审稿人（尤其统计背景）大概率要求敏感性分析。

**如何补**：只动门禁集数据：
1. 对 30 个工作点重放 1000 与 2000 次配对 bootstrap，报告门禁判决翻转的工作点数；
2. 用 BCa 区间替代分位区间做对照；
3. 实现 LTT 的固定序列检验（fixed-sequence testing）作为功效更高的替代门禁，报告在相同 ε 下的通过数变化——这直接对应论文 future work 中"扩大功效"的路线，且有 [26] 的理论背书。

**判据**：若判决在 1000/2000 次下稳定，写入 7.2 作为稳健性证据；若翻转，如实报告翻转点并讨论。

## P1-4 Random 波动带补全

**为什么补**：6.5 节发现 2 的随机带只覆盖 Fixed-call（上游 random_seeds.csv 仅有 fixed_call_seed 模式），Online/Fixed-byte 两种语义下"学习型收益是否超随机"目前是空白，细心的审稿人会问。

**如何补**：用冻结检测/载荷缓存对 Random 排序器补跑 Online（冻结阈值语义下随机分数）与 Fixed-byte（随机次序装箱）各 50 种子 × 3/4 预算档，只在终评集上按已冻结的动作头执行（与上游 Random 口径一致）；把三种语义的随机带补进 6.5 节与图 2（灰色阴影带）。

## P2-5 真机微基准（强烈建议，投稿前完成）

**为什么补**：B2 的最低成本缓解。精读结论：Reducto 用 Pi Zero 的组件吞吐分解、ORIC 用 Xavier NX 的组件延迟表（其 Ranker 估计开销仅占总延迟 1-10%）都表明**组件级实测 + 解析合成**是被接受的评测方式（ICPR 2020 即"真机推理实测+传输时间解析计算"）。有了实测锚点，论文的 E2E 口径从"全为估算"升级为"估算模型经真机组件锚定"，同时给 4.6 节的 0.08 ms/图 提供同源验证。

**如何补**（可行性审计已通过：M2 Pro 端侧 + RTX 4090 云端，见 riskgate `runs/system/feasibility.json`；阻塞项为 GPU 排期与网络整形权限）：
1. 端侧（M2 Pro，或树莓派 5/Jetson 更佳）：对每域各 200 张终评图实测 YOLO26n 推理、JPEG-Q90 编码、ROI 裁剪+编码的逐帧耗时分布（均值/P95）；
2. 云端（RTX 4090）：YOLO26x 单帧与小批推理耗时；
3. 网络：在 1/5/10/20 Mbps 整形（macOS `dnctl/pfctl` 或路由器限速）下实测上传 200 个真实载荷的传输时间，对比字节模型预测值，报告偏差百分比；
4. 产出：一张组件耗时表 + 一句"估算 E2E 与实测锚点的偏差 ≤ X%"，写入 5.4 与 7.1。

**判据**：若偏差小（<15%），估算口径获得实证支撑；若偏差大，如实修正估算模型并重报 E2E 列（AP/字节结果不受影响）。

## P2-6 端到端测试床（JRTIP 路线的硬性前提）

**为什么补**：JRTIP 投稿指南明确要求说明解决的具体实时问题且"仅报速度不够"；SPINN/ApproxDet/OffloaD/EdgeDuet/REACT 全部有完整测试床。不投 JRTIP 可降级为 future work，但投 TMC/TECS 也会显著加分。

**如何补**：在 P2-5 基础上串起完整链路：端侧设备 + HTTP/JPEG 传输 + 队列 + 云服务器；对每域终评子集（如 1000 张）以冻结配置实跑，报告分解时延（端侧推理/编码/上行/排队/云推理/下行）、吞吐、P95/P99，覆盖 ≥2 档带宽 × 2 档 RTT；对照本文原型（7.1 节）的有界异步队列实现。产出替换或并列 5.4 节的估算 E2E 列，并支撑 cover letter 的实时论述。

## P3-7 异族云端检测器对

**为什么补**：7.2 第七条自认"端云同族、错误高度相关"；NeurIPS 2023 [24] 的理论结论是**下游为 specialist 时学习型路由才有胜场**——同族检测器对天然压缩了学习型排序的空间，这既解释了负结果，也提示换异族云端可能改变结论。ORIC 特意配了跨架构对（SSD vs Faster R-CNN）并声明单一对不主张通用性。

**如何补**（DCSB 的"主域全套 + 副域精简"结构控制成本）：云端换 RT-DETR-X 或 Faster R-CNN（野生动物域可用 MegaDetector，天然异族且更强）；重建预测缓存 → 重跑冻结管线（候选校准→门禁→终评一次）。先只做一个域（建议 ENA24，小且有正收益先例）全套，若学习型排序收益打开，再扩另两域。

**判据**：若异族云端下学习型排序超随机带的域增多，边界结论升级为"收益空间由端云互补性决定"（引 [24] 理论）；若仍不超，负结果更加稳固。

## P3-8 域偏移严重度旋钮（COCO-C）

**为什么补**：NeurIPS 2023 用连续旋钮（专家比例/噪声等级）扫失效梯度，比我们三个离散域的边界更有说服力；作者综述路线 B 的核心实验。预算档（5%-40%）已是一个天然旋钮，加上腐蚀严重度即得二维边界图。

**如何补**：COCO 终评集加 gaussian noise / fog / motion blur 各 3-5 档严重度（作者综述提到 stage 0 已有初步观察：noise severity 4 打开 cloud-confidence gap）；端云预测缓存重建；对每档跑 Confidence vs 最强学习型排序器（不必全 8 个）的 Fixed-call 三预算；报告"学习型收益超出随机带的严重度阈值"。

## P3-9 ENA24 门禁扩样与选择稳定性

**为什么补**：M4——全文唯一非平凡正收益来自统计根基最弱的域（selector/gate 各 200 张）。

**如何补**：(a) 从 fit 集或新数据扩充独立门禁集（目标 ≥600 张，近重复组隔离协议复用 dHash 管线）；(b) 对现有 200 张选择集做子抽样（50%×20 次），统计每个工作点 top-1 配置的翻转率，量化选择稳定性并写入 6.3；(c) 按表 8 功效口径给出"检出 0.5×10⁻³ 效应所需的最小门禁集样本量"估算。

## 明确不做（写入 future work 即可）

- **能耗测量**：仅 SPINN/DeepDecision 有，非标配；
- **多任务外推**（分割/关键点）：AccMPEG 覆盖三任务，但对本文协议不是必要验证；
- **视频时序系统**（作者综述路线 C）：最有系统价值但工程量最大，属于下一篇论文的主题而非本文补丁。
