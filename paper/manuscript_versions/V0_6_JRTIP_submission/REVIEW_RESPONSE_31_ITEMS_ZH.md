# V0.5 Word 审阅意见逐条回复与 V0.6 处理方案

说明：以下编号保留 Word XML 中的原始 comment id。原文不存在 id 24；
id 9 和 id 10 是空审阅框，也予以记录。正式修改将在 V0.6 新版本中
完成，不覆盖用户的 V0.5 原文件。

## Comment 0

**意见：**“云端强模型”定义是否合适，是否应强调参数更大、不适合端侧。

**回复：接受。**“强模型”口语化且缺少可验证定义。改为“计算规模更高、
在统一 COCO 评估中精度更高的云端复核模型”，并具体写明本文实例为
YOLO26x。正文不把“参数大”直接等同于“检测一定更准”，而用实测
mAP 和 GFLOPs 说明为何将其放在云端。

## Comment 1

**意见：**“端侧检测器”是否改成“端侧模型”。

**回复：部分接受。**首次出现写“端侧轻量目标检测模型”，后续在强调
功能时使用“端侧检测器”，强调部署位置时使用“端侧模型”。两种写法
含义不同，不机械地全局替换。

## Comment 2

**意见：**删除 v2，直接说学习器。

**回复：接受并进一步规范。**正文删除 Learned v1/v2，方法正式命名为
Cost-Aware Frame-ROI Uploader (CAFRU)，中文为“成本感知帧级-ROI级
上传器”。版本号仅在补充材料的内部映射表中保留。

## Comment 3

**意见：**摘要中的内部参数和缩写是否易懂。

**回复：接受。**摘要删除 `f0.60/r0.08`、`q70/w640`、`online` 等内部
运行语言，只保留标准指标和自然语言设置，例如“平衡工作点”“JPEG
质量因子 70”“真实在线选择性上传”。GFLOPs/image 在首次出现时解释为
按全部输入图像均摊的系统计算量。

## Comment 4

**意见：**摘要中的这些指标是什么意思。

**回复：接受。**摘要只保留 mAP50-95、上传比例、均摊计算量、主循环
FPS 和策略开销等核心量；详细定义统一放到实验设置的“评价指标”小节。
`effective FPS` 明确为 deadline 内返回的有效云端结果数除以总运行时间，
不与相机主循环 FPS 混用。

## Comment 5

**意见：**不要暴露问题，只说完成。

**回复：不完全接受。**投稿论文不能删除影响结论有效性的已知限制，否则
会形成过度陈述。摘要会删除过多工程故障细节以保持紧凑，但讨论部分必须
保留三个边界：T41 NNA 间歇性 SIGILL、100 帧仅为小样本伪参考评估、
板端特征提取尚未完成与 Python 的逐项等价验证。表述将客观、简洁，不
渲染失败。

## Comment 6

**意见：**引言是否过长。

**回复：接受。**引言压缩为四段：问题背景、现有方法缺口、本文方法、
贡献。硬件细节、指标定义和实验编号移到方法或实验设置。目标是英文双栏
约 1-1.25 页。

## Comment 7

**意见：**评价维度是否为标准测试维度。

**回复：接受并分类。**Precision、Recall、AP50 和 mAP50-95 是标准检测
指标；上传比例、KB/image、GFLOPs/image、端到端延迟和策略开销是系统
成本指标；result age、deadline-hit ratio、drop ratio、effective FPS 是
实时调度指标。正文会明确这三组指标的性质，不把系统自定义指标包装成
COCO 官方指标。

## Comment 8

**意见：**核对轻量检测相关文献。

**回复：接受。**已用 CVPR、NeurIPS、Proceedings of the IEEE 和正式
DOI 元数据重新核验，并更新 YOLO、YOLOv10、RT-DETR、YOLO26 和边缘
推理综述的引用。

## Comment 10

## 总体处理结论

31 个实际 Word comment 均已处理，其中 28 项接受或部分接受，1 项因
科研诚信原因不完全接受，2 项为空审阅框。V0.6 的核心变化是：正式方法
命名、主文/补充材料拆分、文献重构、伪参考标注降级、训练/推理架构
分离，以及对 T41 上板策略等价性的谨慎表述。
