## 3. 网络敏感性结果

网络敏感性固定为 25% JPEG payload 预算，比较三种链路：

- 原生局域网：补充运行的实测平均 ping 为 5.294–7.001 ms；
- `wan_20ms_20mbps`：Linux `netem + tbf`，实测平均 ping 为 24.928–31.529 ms；
- `wan_50ms_5mbps`：Linux `netem + tbf`，实测平均 ping 为 55.843–56.409 ms。

每个受控网络 run 均保存施加命令、运行前 ping、运行后 qdisc 计数和清除结果；8/8 为 0% ping 丢包，运行结束后均成功清除自定义 qdisc，板端已恢复原生 `fq_codel`。

### 3.1 精度

| 方法 | 原生 AP50–95 | 20 ms / 20 Mbps | 50 ms / 5 Mbps |
|---|---:|---:|---:|
| **CAVS-OQR** | **0.505348** | **0.505348** | **0.505348** |
| CAVS-OQ | 0.500310 | 0.500310 | 0.500310 |
| ORIC | 0.468420 | 0.468420 | 0.468420 |
| MORIC | 0.463411 | 0.463411 | 0.463411 |

在 0 云失败、0 前缀违规的条件下，三种网络得到完全相同的动作、payload 和预测，因此 AP 完全相同。这是当前控制器设计的预期结果：决策只依赖当前图像、冻结策略和字节状态，不依赖墙钟时间；网络条件改变传输时延，但不会改变已成功执行的动作语义。

## 4. 论文使用建议

1. 主方法继续采用 CAVS-OQR 的逐帧自适应控制器，因为它在主动作空间的 40% 档提供当前最好的在线点结果，并更充分使用预算。
2. 静态 λ 六组可作为“在线预算控制器消融”，但结论应是自适应收益依赖动作空间与预算，而不是声称普遍提升。
3. 网络敏感性应主要支撑系统鲁棒性与时延分析：在请求全部成功时 AP 不变，但带宽和 RTT 显著降低吞吐、增加尾延迟。
4. 这些运行已经保存逐图预测；若正文需要对 +0.001153 等小差异作显著性判断，应补离线 paired bootstrap，不需要再次上板。
