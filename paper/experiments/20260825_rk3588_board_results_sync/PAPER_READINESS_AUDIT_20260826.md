# RK3588 板端实验论文就绪性核查

核查日期：2026-08-26

## 结论

现有两阶段全局调度 HIL 可以作为硬件在环补充实验，但现有因果在线运行只能作为先导结果，尚未达到最终注册系统表的标准。最终在线矩阵应在同一个修正后的运行包、同一远程云端和同一网络条件下统一重跑。

## 旧在线结果为何不能作为最终注册表

1. 所有旧 run 虽然均保持最大前缀预算违规为 0，但每档存在 1--5 次云请求回退。
2. 每个完整 run 的最终框中存在 20--55 个零面积框；当前 AP 依赖临时过滤视图。
3. 旧运行合同有 `zero_lookahead=true` 和 `global_plan=false`，但没有显式冻结 `buffer_frames=0`。
4. HTTP 使用 JSON Base64，真实请求体约为 JPEG payload 的 1.34 倍。若论文声称“链路字节预算”，则预算口径不成立；若定义为 JPEG payload，则必须同时报告 wire bytes。
5. 现有矩阵跨 Mac-MPS 与远程 GPU 两种云后端，无法形成完全公平的统一延迟比较。
6. 新的 CAVS primal-dual 控制器目前只有严格顺序回放诊断，没有新的 RK3588 全流程运行。

## 最终一次性上板矩阵

先冻结一个修正后的协议包，再按同一顺序清单串行执行：

| 方法 | 预算/重复 | 正式运行数 |
|---|---|---:|
| CAVS-OQR（冻结的 primal-dual 控制） | 10%、25%、40% | 3 |
| ORIC | 10%、25%、40% | 3 |
| MORIC | 10%、25%、40% | 3 |
| Confidence | 10%、25%、40% | 3 |
| Random | 10%、25%、40%，至少 5 个预注册种子 | 15 |
| Edge-only | 与预算无关，完整 5,000 帧 | 1 |

合计建议 28 个正式 run。若系统实验时间受限，最低版本为 Random 只跑一个预注册种子，共 16 个 run；但必须把 Random 标为单种子，不能与离线主表的 50-seed Random 混写。

所有方法必须使用同一：

- COCO 5,000 张和同一冻结顺序；
- RKNN-FP16 Edge 模型及预处理；
- YOLO26x 云模型、云服务器和推理协议；
- JPEG/ROI 编码器与 MAUR 语义；
- 10%/25%/40% 预算定义；
- 网络路径和板端 headless 运行状态。

## 启动正式矩阵前必须修正

1. 云端返回前裁剪坐标并删除非有限、越界或零面积框；板端仍执行严格校验。
2. 板端 Edge 输出在评分、融合和落盘前使用同一合法框规则。
3. 推荐改成二进制或 multipart 上传；若暂不修改，论文只能把主预算称为 JPEG payload，并单独报告真实 wire bytes。
4. 运行合同必须固定并哈希：`zero_lookahead=true`、`global_plan=false`、`buffer_frames=0`、模型、策略、控制器、序列和传输协议。
5. 固定唯一云后端。建议用同一远程 GPU 云端完成全部正式运行；不得用 Mac 和远程 GPU 结果拼主表。

## 每个正式 run 的验收门槛

- 5,000/5,000 帧 committed；
- `cloud_failures=0`；
- 非法/零面积框为 0；
- 重复 image ID、position 为 0；
- 最大前缀预算违规为 0；
- 模型、策略、协议和序列 SHA-256 完全匹配；
- 报告 AP50-95、AP50、AP75；
- 报告动作数、JPEG payload、HTTP wire bytes、容量利用率和重试数；
- 报告 Edge、评分、编码、网络、云推理、融合和 E2E 的均值/P50/P95/P99，以及 FPS；
- 记录温度、频率和是否发生降频；能耗只有在外部功率计实测时才报告。

## 上板结束后无需再次运行的统计工作

- 同一 5,000 张上的 1,000 次 paired image bootstrap：CAVS 对 ORIC、MORIC、Confidence、Random；
- Random 多种子均值与标准差；
- CAVS 相对两阶段全局调度上限的在线代价；
- AP--payload、AP--wire bytes、AP--latency 三组 Pareto 图；
- 所有验收字段和哈希的自动审计。
